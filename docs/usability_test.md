# 전체 실행 시나리오와 모니터링 사용성 시험 (담당 C)

서버 3개를 따로 띄우고, 실행기로 실험 4개를 돌리고, 대시보드에서 기록을 찾는 전체 흐름. 마지막 단계에서 명세 성능지표 **모니터링 사용성**("지정한 클라이언트·배정·통신 기록을 찾는 과제의 정확도와 완료 시간")을 잰다.

## 1. 실행 시나리오

터미널 5개, 모두 저장소 폴더에서 가상환경을 켠 상태 (`.venv\Scripts\activate`).

| 단계 | 터미널 | 명령 | 확인할 것 |
|---|---|---|---|
| 1 | ① | `python -m servers.central --port 5003` | `http://127.0.0.1:5003/status` → `"round": 0` |
| 2 | ② | `python -m servers.edge --id E1 --port 5001` | `/status` → `"edge": "E1"` |
| 3 | ③ | `python -m servers.edge --id E2 --port 5002` | `/status` → `"edge": "E2"` |
| 4 | ④ | `python -m dashboard.app` → 브라우저 `http://127.0.0.1:5050` (F11) | 로그가 없으면 대기 화면, 있으면 마지막 실험 |
| 5 | ⑤ | `python -m runner.client_runner --method pref` | 라운드마다 정확도 출력, R20 0.8762. 대시보드가 2초마다 라운드를 따라감 |
| 6 | ⑤ | `python -m runner.client_runner --method random` | R20 0.8762 (공동 정확도는 같고 엣지 구성만 다름) |
| 7 | ⑤ | `python -m runner.client_runner --method pref --inject` | R5 에 시험 요청 2건, 둘 다 409 거부 |
| 8 | ⑤ | `python -m runner.client_runner --method pref --fault` | R5 정확도가 0.7557 로 떨어졌다가 R20 0.8759 |
| 9 | ⑤ | `python -m scripts.make_report` → `python -m tests.test_requirements` | `6/6 통과` |
| 10 | 대시보드 | 아래 2절 사용성 시험 | |
| 11 | ①~④ | Ctrl+C 로 끔 | |

- 실험마다 약 1분. 서버를 안 끄고 다음 실험을 돌려도 됨 (실행기가 시작할 때 서버에 새 실험을 알림)
- 대시보드 '실험 실행' 탭은 서버 3개를 직접 띄우므로, 그 탭을 쓸 땐 ①~③ 을 먼저 끔
- 서버를 따로 띄우지 않고 한 번에: `python -m scripts.run_all` + `python -m scripts.run_all --fault`

## 2. 모니터링 사용성 시험

**참가자**: 화면을 만들지 않은 팀원 2명 (A 이건, B 윤효연). 연합학습 구조는 알지만 대시보드는 처음 쓰는 사람.

**진행** (진행자 C, 1명당 약 10분)
1. 설명 2분: 머리말(실험·라운드 고르기), 클릭하면 고정·Esc 로 해제, 패널 4영역 이름만. 패널별 읽는 법은 알려 주지 않음
2. 과제를 하나씩 읽어 줌. 다 읽은 순간부터 참가자가 답을 말할 때까지 스톱워치로 잼 (초)
3. 3분이 지나면 그 과제는 실패로 적고 다음으로
4. 정답 판정은 아래 정답표 기준. 값이 맞고 이유까지 맞아야 정답
5. 끝나고 "가장 찾기 어려웠던 것" 한 가지를 물어 적음

참가자는 시험 전에 이 문서의 정답표를 보지 않는다.
