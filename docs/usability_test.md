# 전체 실행 시나리오와 모니터링 사용성 시험 (담당 C)

대시보드 하나만 띄우고, '실험 실행' 탭에서 실험 4개를 돌리고(탭이 중앙·엣지 서버 3개를 직접 띄우고 끔), 같은 화면에서 기록을 찾는 전체 흐름. 마지막 단계에서 명세 성능지표 **모니터링 사용성**("지정한 클라이언트·배정·통신 기록을 찾는 과제의 정확도와 완료 시간")을 잰다.

## 1. 실행 시나리오

터미널 1개, 저장소 폴더에서 가상환경을 켠 상태 (`.venv\Scripts\activate`). 실험 실행 1번에 약 1분.

| 단계 | 어디서 | 할 일 | 확인할 것 |
|---|---|---|---|
| 1 | 터미널 | `python -m dashboard.app` → 브라우저 `http://127.0.0.1:5050` (F11) | 머리말 칩 `실제 로그 (logs)` |
| 2 | 실험 실행 탭 | 설정은 기본값 그대로, 배정 방식 `선호 배정`·`무작위 배정` 둘 다 체크 → 실행 | 실험 2개가 차례로 돌고 화면이 라운드를 따라감, R20 둘 다 87.6% (공동 정확도는 같고 엣지 구성만 다름) |
| 3 | 실험 실행 탭 | `선호 배정` 만 체크 + 결함 주입 `거부될 시험 요청 2건 넣기` 체크 → 실행 | R5 에 시험 요청 2건, 둘 다 409 거부, R20 87.6% |
| 4 | 실험 실행 탭 | `선호 배정` 만 체크 + 지연·중단 주입 `클라 지연·중단 + 엣지 대기 제한` 체크 → 실행 | R5 에 C2·C6 빠짐, 공동 정확도 −7.9%p 떨어졌다가 R20 87.6% |
| 5 | 머리말 실험 목록 | `화면 실행 <시각> · …` 실험 4개가 생김 | 결함 주입·지연·중단 실험을 고르면 비교 실험이 `선호 · 시드 42` 로 자동 지정 |
| 6 | 대시보드 | 아래 2절 사용성 시험 | |
| 7 | 터미널 | Ctrl+C 로 대시보드 끔 | |

- 실행 중에는 다른 실행을 못 누름 (한 번에 하나). 중지 버튼을 누르면 서버 3개까지 같이 꺼짐
- 같은 기본 설정·시드라 화면 실행 결과는 저장소의 `선호 · 시드 42` 등 기존 실험과 정확도·배정·요청이 같음 (지연 ms 만 다름)
- 터미널로 같은 실험을 돌리는 방법은 README 실행 절 (`python -m scripts.run_all`, `--fault`)

## 2. 모니터링 사용성 시험

**참가자**: 화면을 만들지 않은 팀원 2명 (A 이건, B 윤효연). 연합학습 구조는 알지만 대시보드는 처음 쓰는 사람.

**진행** (진행자 C, 1명당 약 10분)
1. 설명 2분: 머리말(실험·라운드 고르기), 클릭하면 고정·Esc 로 해제, 패널 4영역 이름만. 패널별 읽는 법은 알려 주지 않음
2. 과제를 하나씩 읽어 줌. 다 읽은 순간부터 참가자가 답을 말할 때까지 스톱워치로 잼 (초)
3. 3분이 지나면 그 과제는 실패로 적고 다음으로
4. 정답 판정은 아래 정답표 기준. 값이 맞고 이유까지 맞아야 정답
5. 끝나고 "가장 찾기 어려웠던 것" 한 가지를 물어 적음

참가자는 시험 전에 이 문서의 정답표를 보지 않는다.

### 과제

실험은 1절에서 방금 돌린 `화면 실행 <시각> · …` 실험. 기존 실험(`선호 · 시드 42` 등)으로 해도 답은 같다.

| # | 종류 | 과제 |
|---|---|---|
| 1 | 클라이언트 | 선호 실험에서 10라운드 때 C4 의 클라 모델 정확도는? |
| 2 | 클라이언트 | 지연·중단 실험에서 집계에서 빠진 클라 두 명과 빠진 라운드, 각각 빠진 이유는? |
| 3 | 배정 | 선호 실험에서 자기 1순위 엣지에 못 간 클라는 누구고, 어느 엣지에 몇 순위로 갔나? |
| 4 | 배정 | 무작위 실험에서 E1 에 배정된 클라 세 명은? |
| 5 | 통신 | 결함 주입 실험에서 거부된 시험 요청 두 건의 라운드, 보낸 쪽 → 받는 쪽, 상태 코드는? |
| 6 | 통신 | 선호 실험에서 3라운드 때 C5 가 보낸 요청 두 건의 API 와 결과는? |
